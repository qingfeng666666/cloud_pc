# 管理界面分项设计

上级文档：[总体设计](../DESIGN.md)。本文是目标设计，不是已完成清单。

实现进度（2026-10-07）：独立Android与Windows管理界面仅访问同设备程序。Android从机设备使用签名权限保护的Binder Provider（从机0.5.15、界面1.0.3，真机待验）；Windows从机设备使用回环19528；主机设备使用回环19527。撤销远程主机API与管理令牌；统一媒体订阅与从机身份认证仍未完成。不依赖digital_human。

本轮范围确认：不移植ALXR管理界面。管理界面为独立程序，提供Android和Windows版，不与从机捆绑发布。2026-10-07新要求：仅活动管理界面所在从机需要持续自动重连，由主机每5秒负责执行。

全局一个活动界面。启动界面即通过本机程序激活会话，不需要先打开Codex页面；从机代发首次CLDC注册通知。每个读取和输入请求携带会话标识，主机拒绝被接替界面。被接替界面不会自动再次激活，设置中的“激活本管理界面”由用户明确接替。正常关闭释放，返回首页不释放；手机切后台不视为断线或关闭。界面不直接与远端主机建立网络连接，不自动重发SEND。

## 1. 定位

管理界面是主机服务的客户端，可以与主机同设备，也可以部署在另一台电脑、手机或头显上。

主机程序负责连接、转接和信息汇总；管理界面不接管这些职责，不直接连接从机。

功能总览：配置从机地址；展示连接状态和能力；设置活动及采集参数；展示主机汇总信息；提交操作并查看结果。界面通过主机 API 工作，不要求与主机部署在同一设备。

## 2. 第一版首页与页面范围

首页参考 HoloLens ALXR 的默认控制界面，仅显示以下三个选项，顺序固定：

1. 从机界面1
2. 从机界面2
3. LLM 对话界面（Codex、DSH、OpenCode）

不增加其他设备入口、文件管理、任务管理或诊断面板选项。主机与从机已有能力保留在服务层，不要求全部出现在第一版界面中。

从机界面1、从机界面2是固定显示槽位，分别通过配置绑定主机登记的从机标识。界面不硬编码某个平台，也不扫描设备。尚未配置、离线或无权限时明确提示，不用另一个在线设备自动替代。

选择入口后切换到对应页面，并提供返回首页的导航。在 ALXR 空间窗口中使用时，继承默认控制窗口的位置、尺寸和姿态参数，不创建到未知位置的新窗口。

控制界面底部保留空白点选区域，不放置隐藏入口、三个点等可触发选项的控件。

### 2.1 从机界面1、从机界面2

- 显示所绑定从机的屏幕截图，不要求视频流，初始更新间隔为 1 秒。
- 截图由主机发起采集并汇总；管理界面仅请求主机数据，不直接访问从机。
- 显示设备名称、采集时间、在线或离线状态；旧截图标注为过期。
- 不将“从机界面”自动理解为远程键鼠控制。第一版仅展示截图，远程输入功能另行定义。
- 页面请求的截图订阅与其他活动消费者分开管理；返回首页可释放本页面的订阅，不擅自取消主机上其他消费者需要的采集。

### 2.2 LLM 对话界面

2026-10-09替代原“主机Codex界面”。先选择Codex、DSH或OpenCode，再读取主机返回的会话列表，用户选择继续指定会话或新建。模型、认证及工具权限由用户预先在主机原生程序配置，管理界面不设置这些内容。不同后端的会话和历史不混用。

交互参考原 Android“打开当前窗口”：显示选中会话的API文字，不是桌面截图或终端屏幕抓取。

页面从上到下布局：

1. 页面标题与返回导航。
2. 顶部输入框：始终可见；软键盘弹出时调整可用区域，不遮挡完整输入内容。
3. SEND、STOP 两个按钮。
4. 可滚动的对话文本区域。
5. 最新提交编号、执行状态或错误提示。

文字更新与历史：

- 初始每 1 秒从主机更新一次文字；未变化时不重绘整个文本区域。
- 默认显示最新内容；用户向上查看历史时保留滚动位置，不因刷新跳回顶部或底部。
- 用户回到最底部后恢复跟随最新内容。
- 当前窗口显示最近20轮Codex/20条DSH消息和最多65536字符，完整原生历史不删改；会话列表支持加载下一页。
- 尚未配置、服务未启动或API读取失败时明确提示，不把陈旧文字标为实时。新链路不受桌面锁屏和焦点影响。

SEND 行为：

- 每次点击生成唯一请求标识，并显示递增编号，便于查询日志。
- 通过管理API提交明确的provider、session_id、request_id及text，主机内部模块调用原生API一次，不再模拟回车或寻找目标桌面窗口。
- 工作中的会话暂不接受新SEND，用户等完成或STOP后再提交。提交成功与回复完成分开呈现。
- 区分已接受、处理中、提交成功和失败；仅 HTTP 请求成功不能显示为已输入成功。
- 不超时自动重发；失败时保留待提交文字。主机SQLite持久去重，重启后未确认的请求也不重新发送。

STOP 行为：

- 调用选中后端的原生中止API，效果类似工作过程中按一次ESC，但不发送键盘事件。
- 仅忙碌时执行，不关闭会话或退出程序；同一连续忙碌阶段最多执行一次。
- 工作状态、持久去重及实际操作统一由主机内置LLM模块完成，不依赖管理界面本地判断。

### 2.3 数据与操作路径

从机设备：独立管理界面 → 本机从机（Android Binder / Windows回环19528） → 主机已建立的CLDC连接 → 云电脑主机内置LLM模块 → 主机本地应用API。主机设备：独立管理界面 → 本机主机127.0.0.1:19527 → 同一模块。无新增跨设备连接，不依赖19627适配器。

主机按管理界面请求读取/执行，不自行发起对话。各请求显式绑定后端和会话，页面切换后的迟到结果不得应用到新页面。原生权限配置不自动改变；复杂审批表单尚需原生界面处理。新链路、配置及测试记录见[LLM接口说明](../../host_program/LLM_API.md)。安卓管理1.1.0与从机0.5.21需要配套更新，Windows从机须具有新版回环LLM路由。

## 3. 通用能力与后续范围

- 配置或选择已知从机地址，通过主机请求连接。
- 查看连接状态、能力和错误。
- 设置各从机是否活动及采集参数。
- 查看主机汇总的截图、音频状态、任务结果及诊断信息。
- 通过主机提交文件、任务和业务操作。
- 查看请求编号和结果，区分提交成功、目标执行成功及失败。

以上是后续通用能力，暂不添加到第一版三个入口之外。界面可只显示所需功能，不要求每种平台使用同一界面实现。

## 4. 活动状态与显示

“活动”是主机保存的采集状态，不只是界面当前选中的标签页。

设置活动 → 向主机提交配置 → 主机启动从机采集 → 界面消费主机汇总数据。可以有多个活动从机。

界面应显示采集时间和在线状态。断线时标注旧截图或音频状态，不能继续显示为正在实时同步。

界面关闭、切换页面或设备休眠，不默认改变主机采集状态；如需自动停止，应通过明确策略配置。

## 5. 远程部署

界面只访问同设备从机程序或主机程序，不直接访问其他设备的API。

管理界面访问同设备从机（Android Binder / Windows回环19528），由从机沿既有CLDC会话取得主机信息；不能改成远程主机IP。主机角色仅访问本机19527。

管理界面提交目标地址不代表自动获准访问；最终由主机校验权限，再由从机校验本机执行权限。

## 6. 与现有界面的关系

现有桌面界面、Android 当前会话界面、头显窗口等可以作为不同管理客户端或专项消费者，但需要按上述边界核对。

已有混合界面逐步解耦；新增独立管理客户端只访问同设备从机或主机服务，不宣称全部旧程序完成解耦。

## 7. 第一版验收

1. 首页包含从机界面1、从机界面2、LLM对话界面，以及已实现的主机运行状态。
2. 两个从机槽位展示各自绑定设备的截图，缺配置或离线时明确提示。
3. 三个LLM入口由主机返回会话，用户可继续/新建；对话每秒更新，输入框不被软键盘遮挡。
4. 浏览历史时刷新不改变阅读位置，首次打开默认显示最新内容。
5. 一个SEND对应一次API提交，编号可追查；失败、重启不自动重试。
6. STOP空闲时无操作，连续工作阶段只执行一次，不退出原生程序。
7. 所有设备访问及输入操作经主机执行，管理界面不直接连接从机。
