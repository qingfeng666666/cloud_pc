# 主机程序分项设计

上级文档：[总体设计](../DESIGN.md)。本文是目标设计，不是已完成清单。

实现进度（2026-10-06）：桌面主机已增加 --headless 独立服务入口，并分离 API 响应订阅与界面回调；新增带编号的只读 RPC 及显式授权的从机 IP 转接，已与实际 Python 从机验证。详见[启动与验证说明](../../desktop_version/README.md)。尚未完成全部管理界面解耦、全平台转接和主机身份认证。本次未替换常驻 8765 服务或部署从机安装包。

## 1. 职责

2026-10-09：LLM转接整合到主机内部，直接调用用户预配置的Codex App Server、DSH和OpenCode本地API。统一会话列表、新建、打开、读取、SEND/STOP；新管理界面不依赖独立桌面适配器19627。主机只在收到管理请求时调用API，不主动选择模型、登录、修改工具权限或读取对话。详见[LLM接口设计与验收](../../host_program/LLM_API.md)。

主机程序是连接和信息汇总中心，不等同于图形界面。没有管理界面运行时，主机仍可维持连接、转接消息和执行已配置的活动采集。

主机可包含连接管理、请求调度、转接、信息汇总和管理 API 模块；界面组件不应成为这些模块运行的前提。

功能总览：主动连接并维持从机会话；下发管理操作并接收结果；按已知目标 IP 转接从机消息；管理活动采集；汇总截图、音频、状态、任务输出和日志；提供管理 API 并校验访问权限。

## 2. 连接管理

- 保存已配置从机 IP、端口、身份和能力信息。
- 主动连接从机，完成认证和能力协商。
- 维护双向会话、心跳、超时及重连状态。
- 本轮不增强长时间断线持续重连（用户明确不需要），保留现有有限重试。
- 对每次请求关联返回结果；断线时明确报告未完成请求。
- 不依赖从机广播寻找主机或主动建立回连。
- 不扫描从机所属网络来自动发现下级设备。

地址配置与在线状态分开：有 IP 不代表设备在线，连接可达也不代表已通过授权。

## 3. 消息转接

从机通过现有主机会话提交转接请求。以下为概念结构，字段及消息类型需实现时定稿：

```json
{
  "request_id": "relay-001",
  "target_ip": "192.168.4.20",
  "operation": "example_operation",
  "payload": {}
}
```

字段作用：

| 字段 | 作用 |
| --- | --- |
| request_id | 关联请求、结果及诊断日志 |
| target_ip | 请求方事先知道的目标从机 IP |
| operation | 要转发的操作类型，用于授权和能力检查 |
| payload | 目标操作的正文，不由主机随意改变 |

目标端口可使用配置值；需要显式指定时仍须经过授权。主机从已认证会话取得真实请求方身份，不信任请求正文自报的来源。

处理顺序：验证来源 → 校验目标和操作权限 → 查找或建立目标会话 → 转发 → 关联返回。单次转接不得递归转发形成循环。错误至少区分目标未配置或未授权、无法连接、能力不支持、执行失败。

文件或媒体传输仍应遵循分块、大小限制、背压和取消规则，不把大文件直接塞入普通 JSON。

## 4. 信息汇总

每个从机维护独立信息：

- 身份、IP、能力、连接状态和最后更新时间。
- 活动状态及截图、音频采集配置。
- 最新截图和必要的有限历史。
- 音频分片及格式、采集时间、序号。
- 任务输出、操作结果和诊断错误。

主机接受管理界面设置活动状态后，主动通知从机启动所需采集。采集周期、音频参数及保留量可配置；不强制所有平台使用同一种采集方式。

主机向消费者提供最新数据或订阅更新，避免多个管理界面分别启动重复采集。断线时保留必要诊断信息并标注数据过期；重连后按活动配置恢复采集。

## 5. 管理 API 与安全

管理界面通过 API 获取汇总信息及提交操作。界面可与主机同机，也可远程部署。

远程 API 必须校验调用者身份及权限，并使用加密通道或受控隧道。现有回环地址服务不能仅改为全网监听就视为完成远程管理。

主机管理 HTTP 只监听 127.0.0.1:19527。从机设备上的界面调用本机从机接口，由从机沿既有 CLDC 会话主动发送 0x0607 管理请求；主机设备上的界面调用本机主机接口。主机按请求 ID 用 0x0606 返回结果，不另建连接、不轮询管理队列。连接建立由主机主动发起，普通业务消息允许双向主动发送；握手协商 management_push_v1。列表读取与会话刷新分通道调度，SEND/STOP 等有副作用操作按序处理。

认证、目标白名单、操作权限、速率和载荷限制共同约束转接。仅依据源 IP 的限制不替代主机身份认证。

## 6. 日志

记录连接状态变化、活动采集启停、转接请求号、真实来源、目标、操作类型、耗时和结果。默认不记录密钥、完整音频或输入文本等敏感正文。

主机的连接、转接和汇总日志应独立于管理界面，便于无界面运行时排查。

## 7. 单一活动管理界面与连接保障（2026-10-07）

全局仅一个活动管理会话。管理界面先调用同设备的从机注册操作；从机向主机19526发送CLDC短连接注册通知（0701请求、0781结果），提供会话编号与从机监听端口。主机只认可配置列表中的来源IP及端口，不采纳自报IP、不扫描下游设备；此入口不能执行任务、读取文件或转发业务。正常业务连接仍由主机主动连接从机9527，管理HTTP仍只监听127.0.0.1:19527。

首次注册后，即使有限次重连已经耗尽，主机也恢复该从机的连接循环；只对此活动管理从机每5秒持续发起重连，其他从机保持有限次策略。同一从机仅允许一条连接任务和一个消息读取循环，在线时不重复连接。可用--management-interval配置间隔。

新界面激活将旧会话失效。旧会话读取或SEND/STOP均返回management_inactive；旧界面不得自行抢回，只允许用户主动重新激活。主机本机界面注册为host，不要求任何远程从机持续重连。关闭界面正常释放会话；异常退出或释放通知丢失时，保留会话直到重新激活/有效释放，避免网络断线被误认为用户关闭。

会话和失效编号写入主机状态文件（默认用户.local/state/cloud_pc/management.json），主机重启后按配置地址恢复管理从机策略，不依赖临时从机ID。健康诊断仅显示活动地址、间隔，不显示会话密钥。当前配置来源白名单不是完善的设备身份认证，跨公网必须依赖WireGuard等受控通道。

此规则替代“所有从机均只进行有限次重连”的旧约定。重连只恢复连接，不重放SEND/STOP或任务。
